AS-IS vs TO-BE 화면 및 데이터 비교

운영 중인 기존 홈페이지 문의하기 폼과 이번 데모체험 전환 분석 고도화 폼의 변화를 1:1로 비교합니다.

🔴 AS-IS (기존 문의 접수 폼)

단순 문의 접수 폼

첨부해 주신 이미지 기준의 문의 내용 구분 및 8개 기본 필수 항목만 존재

수집 항목 (총 8개):
  • 문의 내용 구분 (기능/요금 등)
  • 회사명
  • 예상 사용 인원
  • 담당자 이름
  • 휴대전화
  • 직책
  • 회사 이메일
  • 문의 내용 (서술형 텍스트)
🚨 AS-IS의 문제점 (PRD 기반):
  • demo_id 및 추적 식별자 부재로 실사용 회원사 전환 매칭 불가
  • 업종(입력값), 데모체험 목적, 관심 기능 미수집으로 사용자 분석 불가
  • 데모 체험 후 유료 결제 전환 연동 프로세스 부재
🟢 TO-BE (이번 고도화 개선안)

전환 분석 데이터 구축 폼

영업 세그먼트 파악 + 자동 트래킹 파라미터 + 유료 전환 연동

추가/개선된 수집 항목:
  • [삭제 완료] 불필요한 '도입 예정 시기', '데모 신청 경력' 삭제
  • [선택 추가] 업종 (직접 입력값)
  • [선택 추가] 데모체험 목적 (위시드 CRM 검토/기능확인/사내테스트/타사비교/기타)
  • [선택 추가] 관심 기능 항목 (고객/영업기회/영업활동/일정/견적계약/매출/통계분석/기타 - 최대 3개)
  • [P0 핵심 구축] 데모 CRM 내 직접 결제/회원가입 & demo_id 승계 연동
  • [자동 수집] demo_id, 신청일시, 유입경로, 작성시간
✨ TO-BE 개선 기대 효과:
  • demo_id ↔ company_id 이메일/휴대폰 키 기반 자동/관리자 매칭
  • 체험 대시보드 내 유료계정 전환 버튼 상시 노출로 즉시 가입 유도
  • Activation 4대 핵심 이벤트를 수집하여 이탈률 및 사용 패턴 정밀 분석
📋 이번 P0 변경사항 요약 (클릭하여 접기/펼치기) ▲
+ demo_id 생성 및 관리

+ CRM 회원가입 CTA 추가

+ 데모관리 ↔ 회원사관리 양방향 조회
+ 핵심 Activation 로그 연결

Q2. 이메일 + 휴대전화 복합 키 기반 매칭 처리 로직
이태민 개발자님 의견대로 [후보 검색+관리자 확정]과 [데모 화면 내 회원가입]을 모두 수용할 때, 이메일과 휴대전화가 모두 일치하는 건을 1순위로 자동 매칭 팝업에 노출하면 될까요?
💡 추천 답변: 이메일 OR 휴대폰 중 하나만 맞을 때는 '매칭 주의' 경고를 띄우고, 둘 다 맞으면 '자동 연결 승인' 버튼을 활성화합니다.
Q3. 업종 (직접 입력) 데이터 텍스트 정제 및 분류 방식
'업종' 항목을 기존 드롭다운에서 자유 텍스트 직접 입력으로 변경하였습니다. 백엔드에서 유사 키워드(예: IT, SaaS -> IT/소프트웨어)로 그룹핑하는 태깅 로직이나 정규화 작업을 진행하시나요?
💡 추천 답변: 일단 VARCHAR(100) raw text로 저장하고, 통계 추출 시 LIKE 또는 백엔드 매핑 딕셔너리로 분류하자고 조율합니다.
Q4. Activation 로그 수집 범위 (기존 CRUD 활용)
