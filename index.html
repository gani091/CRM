🔥 P0 개발 논의 가이드

화면 비교가 아니라 실제 회원 전환에 필요한 계약, 상태, 연결 규칙과 완료 기준만 정리했습니다.

단일 P0 목표
데모 신청자를 식별 가능한 guest로 발급하고, 가입·결제 완료 시 같은 사용자를 정식 회원사로 연결한다.
전환 기준: 가입 완료 + 결제 완료
데모 신청→demo_id 발급→guest 로그인→정보 Pre-fill 가입→company_id 생성→결제 완료→CONVERTED

1. AS-IS → TO-BE 변경 계약

영역AS-ISTO-BE P0완료 기준
신청문의 데이터만 저장, 전환 식별자 없음신청 즉시 불변 demo_id와 guest 계정 생성재시도해도 중복 발급되지 않음
체험데모와 신청자 연결 불가guest 세션에 demo_id 포함, 4대 Activation 기록모든 이벤트에 demo_id가 저장됨
가입별도 회원가입으로 정보 재입력회사명·담당자·전화·이메일·업종 Pre-fillStep 3 완료 시 company_id 생성·연결
전환가입과 결제를 구분하지 않음PAYMENT_PENDING과 CONVERTED 분리결제 성공 webhook 이후에만 CONVERTED
운영데모·회원사 화면이 단절SYSADMIN 양방향 조회와 수동 매칭 지원demo_id ↔ company_id 상호 이동 가능

2. 상태·데이터 원칙

  • demo_id: 신청 완료 시 생성하는 불변 식별자
  • company_id: 회원사 정보 입력 완료 시 생성
  • 가입 완료: PAYMENT_PENDING, 전환율에서 제외
  • 결제 완료: PAID + CONVERTED, 전환율에 포함
  • 결제 시스템 webhook을 결제 상태의 Source of Truth로 사용

3. 매칭·중복 방지 원칙

  • 자동 연결: 데모 CRM 내부 가입은 세션의 demo_id로 직접 연결
  • 수동 후보 1순위: 이메일 + 전화번호 동일
  • 2순위 이메일, 3순위 전화번호 동일
  • 회사명 또는 담당자명만으로 자동 연결하지 않음
  • 이미 연결된 demo/company의 재연결은 차단하고 감사 로그 저장

4. P0 범위에 유지

  • 데모 신청 핵심정보 및 선택 분석정보
  • guest 계정·가상 데이터 안내·CRM 상단 가입 CTA
  • 회원가입 4단계와 기존 신청정보 Pre-fill
  • 4대 Activation: LOGIN, CUSTOMER, OPPORTUNITY, ACTIVITY
  • SYSADMIN 전환 상태·수동 연결·양방향 조회

5. 삭제·제외한 범위

  • 중복 AS-IS/TO-BE 비교 카드와 기대효과 문구
  • 도입 예정 시기, 데모 신청 경력 입력 필드
  • 회사명/담당자명 단독 자동 매칭
  • 회원가입 완료를 최종 전환으로 집계하는 로직
  • P1/P2: CS 사유 분석, AI 분석, 고급 세그먼트 대시보드
