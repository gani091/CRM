AS-IS vs TO-BE 화면 및 데이터 비교

운영 중인 기존 홈페이지 문의하기 폼과 이번 데모체험 전환 분석 고도화 폼의 변화를 1:1로 비교합니다.

🔴 AS-IS (기존 문의 접수 폼)

단순 문의 접수 폼

첨부해 주신 이미지 기준의 문의 내용 구분 및 8개 기본 필수 항목만 존재

수집 항목 (총 8개):
  • 문의 내용 구분 (기능/요금 등)
  • 회사명
  • 예상 사용 인원
  • 담당자 이름
  • 휴대전화
  • 직책
  • 회사 이메일
  • 문의 내용 (서술형 텍스트)
🚨 AS-IS의 문제점 (PRD 기반):
  • demo_id 및 추적 식별자 부재로 실사용 회원사 전환 매칭 불가
  • 업종(입력값), 데모체험 목적, 관심 기능 미수집으로 사용자 분석 불가
  • 데모 체험 후 유료 결제 전환 연동 프로세스 부재
🟢 TO-BE (이번 고도화 개선안)

전환 분석 데이터 구축 폼

영업 세그먼트 파악 + 자동 트래킹 파라미터 + 유료 전환 연동

추가/개선된 수집 항목:
  • [삭제 완료] 불필요한 '도입 예정 시기', '데모 신청 경력' 삭제
  • [선택 추가] 업종 (직접 입력값)
  • [선택 추가] 데모체험 목적 (위시드 CRM 검토/기능확인/사내테스트/타사비교/기타)
  • [선택 추가] 관심 기능 항목 (고객/영업기회/영업활동/일정/견적계약/매출/통계분석/기타 - 최대 3개)
  • [P0 핵심 구축] 데모 CRM 내 직접 결제/회원가입 & demo_id 승계 연동
  • [자동 수집] demo_id, 신청일시, 유입경로, 작성시간
✨ TO-BE 개선 기대 효과:
  • demo_id ↔ company_id 이메일/휴대폰 키 기반 자동/관리자 매칭

  • Activation 4대 핵심 이벤트를 수집하여 이탈률 및 사용 패턴 정밀 분석
