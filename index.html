🔴 AS-IS (기존 문의 접수 폼)

단순 문의 접수 폼

첨부해 주신 이미지 기준의 문의 내용 구분 및 8개 기본 필수 항목만 존재

수집 항목 (총 8개):
  • 문의 내용 구분 (기능/요금 등)
  • 회사명
  • 예상 사용 인원
  • 담당자 이름
  • 휴대전화
  • 직책
  • 회사 이메일
  • 문의 내용 (서술형 텍스트)
🚨 AS-IS의 문제점 (PRD 기반):
  • demo_id 및 추적 식별자 부재로 실사용 회원사 전환 매칭 불가
  • 업종(입력값), 데모체험 목적, 관심 기능 미수집으로 사용자 분석 불가
  • 데모 체험 후 유료 결제 전환 연동 프로세스 부재
🟢 TO-BE (이번 고도화 개선안)

전환 분석 데이터 구축 폼

영업 세그먼트 파악 + 자동 트래킹 파라미터 + 유료 전환 연동

추가/개선된 수집 항목:
  • [필수 추가] 도입 예정 시기
  • [선택 추가] 업종 (직접 입력값)
  • [선택 추가] 데모체험 목적 (위시드 CRM 검토/기능확인/사내테스트/타사비교/기타)
  • [선택 추가] 관심 기능 항목 (고객/영업기회/영업활동/일정/견적계약/매출/통계분석/기타 - 최대 3개)
  • [보안 반영] 데모 신청 경력 (신규/재방문 직접 선택)
  • [자동 수집] demo_id, 신청일시, 유입경로, 작성시간
✨ TO-BE 개선 기대 효과:
  • demo_id ↔ company_id 이메일/휴대폰 키 기반 자동/관리자 매칭

Q2. 이메일 + 휴대전화 복합 키 기반 매칭 처리 로직
이태민 개발자님 의견대로 [후보 검색+관리자 확정]과 [데모 화면 내 회원가입]을 모두 수용할 때, 이메일과 휴대전화가 모두 일치하는 건을 1순위로 자동 매칭 팝업에 노출하면 될까요?
